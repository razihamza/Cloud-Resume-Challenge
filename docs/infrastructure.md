# Infrastructure (AWS SAM)

The backend (database, function, API, permissions, log group) is defined in [`backend/template.yaml`](../backend/template.yaml) and deployed with the AWS Serverless Application Model (SAM). SAM is shorthand that CloudFormation expands into full resources, so everything below is also standard CloudFormation.

S3 and CloudFront are **not** in the template yet. They were set up by hand, see [cloudfront-s3.md](manual-setup/cloudfront-s3.md).

## What the template creates

| Logical ID in the template | What AWS creates | Purpose |
|---|---|---|
| `VisitorTable` | DynamoDB table (on-demand, AWS-owned encryption key) | Holds one item with the visit count |
| `FunctionLogGroup` | CloudWatch log group, 30-day retention | Lambda logs |
| `VisitorApi` | HTTP API with a default stage | Public HTTPS endpoint, CORS limited to the site, throttled to 2 requests per second (burst 5) |
| `VisitorFunction` | Lambda function, IAM execution role, permission for the API to invoke it | Adds 1 to the counter. The role may only call `dynamodb:UpdateItem` on the table |
| `CountVisit` (event) | Route `POST /visits` | Connects the API to the function |

Parameters: `SiteOrigin` (the exact site origin allowed by CORS) and `LogRetentionDays`.
Outputs: `ApiUrl`, `TableName`, `FunctionName`.

The table has `DeletionPolicy: Retain`, so deleting the stack does not delete the data. Resource names are generated by CloudFormation, so they include the stack name.

## Prerequisites

- AWS CLI v2 (2.32 or newer, for `aws login`) and the AWS SAM CLI
- Python on the PC. Set the `Runtime` line in `template.yaml` to match it (`python3.12`, `python3.13` or `python3.14`), because `sam build` looks for that version
- Region `ap-south-2`. Check with `aws configure list`
- Sign in with `aws login` (short-lived credentials, no access keys). Verify with `aws sts get-caller-identity`

## Deploy

From `backend/`:

```
aws login
sam validate --lint
sam build
sam deploy
```

| Command | What it does |
|---|---|
| `sam validate --lint` | Checks the template locally. Nothing is sent to AWS |
| `sam build` | Copies the function code into `.aws-sam/build/` |
| `sam deploy` | Uploads the code, shows a change set (a preview), and on confirmation creates or updates the stack |

Settings come from [`backend/samconfig.toml`](../backend/samconfig.toml): stack name `cloud-resume-backend`, region, tags (`project=cloud-resume env=prod`), and a SAM-managed S3 bucket that holds the deployment files.

After the first deploy, copy `ApiUrl` from the Outputs into `frontend/js/counter.js`, upload the file to the site bucket, and invalidate the CloudFront cache.

## Updating

1. Edit `template.yaml` or `lambda/`.
2. Run the tests, then `sam validate --lint`, `sam build`, `sam deploy`.
3. **Read the change set** before typing `y`. Look for anything marked as replacement or removal.

If the site's address changes (for example a custom domain), change the `SiteOrigin` parameter and redeploy, or CORS will block the page.

## Inspecting a deployed stack

CloudFormation console (region `ap-south-2`), then the `cloud-resume-backend` stack:

| Tab | Shows |
|---|---|
| Events | The timeline of what was created, in dependency order |
| Resources | Every resource with its real AWS name |
| Template | The original and the expanded template |
| Outputs | `ApiUrl`, table name, function name |
| Change sets | The previews from each deploy |

## Tearing down

The rule: delete what points at a resource before the resource itself.

1. **Website**
   - Remove any DNS or custom-domain records first (none today).
   - CloudFront: disable the distribution, cancel its flat-rate plan, then delete it.
   - Empty the site bucket, then delete it.
2. **Backend**
   - `sam delete --stack-name cloud-resume-backend --region ap-south-2`. CloudFormation removes the API, function, role and log group in the right order.
   - The DynamoDB table is **kept** because of `Retain`. Copy the count if you need it, then delete the table by hand.
3. **SAM's deployment bucket**
   - Only if SAM is no longer used in this region: empty the bucket, then delete the `aws-sam-cli-managed-default` stack.
4. **Check for leftovers**
   - CloudWatch log groups, IAM roles and policies, and Billing the next day.

For reference, the hand-built backend that came before the template was removed in this order: HTTP API, then Lambda function, then DynamoDB table, then the function's IAM role and its policy, then the log group.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `Could not connect to the endpoint URL` | Wrong region code. Use `ap-south-2`, with both hyphens. Run `aws configure set region ap-south-2` |
| Commands fail with an expired or missing token | Run `aws login` again |
| `sam build` cannot find Python | The `Runtime` line does not match the local Python version |
| Stack shows `ROLLBACK_COMPLETE` after a failed first deploy | Run `sam delete`, fix the cause (read the Events tab), and deploy again |
| Browser shows a CORS error | `SiteOrigin` must match the page's origin exactly: `https://`, no trailing slash, no path |
| API returns 404 | The route is `POST /visits`. Check the method and the path in the URL |
| `403` on the live site | Not this stack. Check the CloudFront origin and bucket policy, see the [runbook](runbook.md) |
